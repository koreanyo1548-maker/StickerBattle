# 구현 계획: 블라인드 구조 개편

## 진행 상황

| 단계 | 상태 |
|---|---|
| 0. 그림 분리, 빌드 스크립트, node 로더 | 완료 |
| 1. 콘텐츠 데이터 | 완료 |
| 2. 점수 계산 | 완료 (`tools/test-rules.mjs`) |
| 3. 게임 흐름 | 완료 (명령만으로 런 완주 테스트) |
| 4~7. 화면 | 미착수 |

**주의**: 화면(`src/presentation/main.js`, `src/rendering/compositor.js`)은 아직 옛 규칙을 쓴다. 그래서 `index.html`은 마지막으로 플레이 가능한 빌드(옛 규칙)로 두고, 화면 작업이 끝날 때 다시 빌드한다. 그 전까지 `node tools/build.mjs --check`는 실패한다.

### 목표 점수 재조정
설계 시뮬레이터(`tools/sim-balance.mjs`)는 조합 무기 9종을 모두 "조건 없이 ×1.5"로 단순화해서 점수를 크게 잡았다.
실제 엔진에서 같은 봇으로 400판을 돌리면 300 / 1100 / 3000 / 8000의 블라인드 1 클리어율이 58%에 그친다.
실제 엔진 기준 봇(`tools/balance-bot.mjs`)으로 다시 잡은 목표:

| 목표 | 봇 누적 클리어율 |
|---|---|
| 150 / 500 / 1500 / 4000 | 89 / 66 / 43 / 27% |
| **100 / 400 / 1200 / 3500** | **95 / 75 / 51 / 33%** |
| 100 / 350 / 1000 / 3000 | 95 / 78 / 55 / 37% |

봇은 번개 누적과 다음 블라인드 속성을 고려하지 않고 보상도 무작위로 고르므로, 사람은 이보다 잘할 가능성이 높다. 화면 작업 후 직접 플레이로 다시 맞춘다.

기준 문서: `docs/design-sketch.md`. 이 문서는 그 설계를 `index.html`에 옮기기 위한 변경안, 필요한 리소스, 확정 규칙을 정리한다.
수치는 모두 초안이다. 구현 후 실제 플레이로 조정한다.

## 1. 범위

**이번에 구현**
- 블라인드 4개 × 6턴 구조, 목표 점수 판정, 즉시 실패
- 원정대 유지, 별·속성 레벨, 조합 무기 9종 새 효과와 레시피 레벨
- 족보 레벨(페어/컬렉션/트리플), 별 족보의 레벨 판정
- 블라인드 속성과 대칭 상성
- 야바위 보상(공개 → 뒤집기 → 섞기 → 선택), 등급 하/중/상
- 위 규칙에 맞춘 화면과 연출

**이번에 하지 않음 (다음 단계)**
- 메타 성장(스티커 뽑기, 보상 덱 구성, 난이도 단계)
- 효과음, 영어화, 크레이지게임즈 SDK
- 보스 규칙 (보스는 목표 점수와 그림만 다르게)
- 같은 무기 중첩(쌍검 등): 거절 규칙을 데이터로 판정해 두기만 함

## 2. 확정 규칙

### 런 흐름
1. 런 시작: 원정대 비어 있음, 모든 레벨 Lv1, 누적 0.
2. 블라인드 시작: 이번 블라인드 속성과 **다음 블라인드 속성**을 공개.
3. 턴 시작: 스티커 덱에서 5장. 캐릭터 카드 규칙에 따라 1장이 캐릭터 카드로 바뀜.
4. 턴 중: 최대 3회 붙이기(캐릭터 배치 포함). 손에 남은 카드는 턴 종료 시 버림.
5. 턴 종료: 번개 조합 무기의 누적 조건 판정.
6. 6턴 종료: 점수 계산 → 목표 이상이면 보상, 미만이면 런 종료.
7. 보상 후 다음 블라인드. 4번째 블라인드를 넘기면 런 클리어.

### 상수 (초안)

| 항목 | 값 | 현재 코드 |
|---|---|---|
| 블라인드 / 턴 | 4 / 6 | 스테이지 3 / 최대 8턴 |
| 핸드 / 붙이기 | 5 / 3 | 3 / 2 |
| 원정대 | 최대 3명, 유지 | 3명, 전투마다 초기화 |
| 캐릭터 카드 | 블라인드 1은 1~3턴 확정, 2~4는 1턴 확정, 그 외 턴 20% | 1·2·3·7·8턴 |
| 스티커 덱 | 고정 18장 (무기 3종×2, 속성 3종×2, 별 6) | 같음, 보상으로 추가/제거 |
| 캐릭터 기초 | 5 | 2 |
| 무기 | +5 | +2 |
| 별 | Lv당 +3, 상한 없음 | 개당 +1, 최대 3 |
| 목표 점수 | 100 / 400 / 1200 / 3500 | 적 팀 점수, 체력 60 |

### 붙이기
- **캐릭터**: 빈 자리에 배치. 자리가 차 있으면 교체하고 붙어 있던 스티커와 레벨은 새 캐릭터로 옮겨짐 (기존 `placeUnit` 동작 유지).
- **별**: 별 Lv+1.
- **속성**: 같은 속성이면 속성 Lv+1. 다른 속성이면 교체하고 Lv1.
- **무기**: 없으면 장착, 다른 무기면 교체. 같은 무기는 거절(데이터 규칙).
- 무기와 속성이 모두 있으면 조합 무기가 결정됨.

### 점수 공식
```
기초 = Σ캐릭터(5 + 별Lv×3 + 무기 5)
     + Σ족보 보너스 × 족보Lv
     + Σ별 족보 보너스 × 별Lv × 족보Lv
     + 물 조합 무기 보너스 + 번개 누적
배율 = Π불 조합 무기 × Π성립한 족보마다 (1 + 0.25×(족보Lv−1)) × Π캐릭터 상성
최종 = floor(기초 × 배율) + 역류검 보너스
```

### 족보
| 축 | 페어 | 컬렉션 / 스트레이트 | 트리플 |
|---|---|---|---|
| 종족·직업·무기·속성 | 2명 같음: 5 | 3명 모두 다름: 10 | 3명 같음: 15 |
| 별 (Lv0 제외) | 2명 같은 Lv: 3×Lv | 3명 연속 Lv: 6×가운데 Lv | 3명 같은 Lv: 9×Lv |

- 한 축에서는 가장 높은 족보 하나만 인정(기존 `exclusiveGroup` 유지).
- 족보 레벨은 종류 단위 3개(페어/컬렉션/트리플). 별 스트레이트는 컬렉션 레벨을 따름.
- 더블/풀 완성(`compoundCombos`)은 **삭제**. 폭발궁이 같은 역할을 맡음.

### 상성
- 순환: 불 > 번개 > 물 > 불.
- 캐릭터마다: 유리 ×(1 + 0.25×속성Lv), 불리 ÷(1 + 0.25×속성Lv), 무관 ×1.
- 종족·무기 상성은 삭제.

### 조합 무기
`docs/design-sketch.md` 3장의 9종 표를 그대로 사용. 레벨은 레시피 단위로 저장하고, 같은 레시피를 든 캐릭터가 둘이면 둘 다 적용.

### 보상 (야바위)
1. 보상 풀에서 3장을 뽑고 각각 등급을 굴림: 하 60% (+1), 중 30% (+2), 상 10% (+3).
2. 앞면 공개 → 뒤집기 → 섞기 → 플레이어가 1장 선택. 고른 위치의 카드가 그대로 보상(결과 조작 없음).
3. 보상 풀: 보유한 조합 무기의 레시피 Lv, 족보 Lv(페어/컬렉션/트리플).
4. 섞기 연출: 블라인드 1은 느리게(교체 3회), 이후 빠르게(교체 5~6회). 목표 추적 성공률 40~50%, 플레이 후 조정.
5. 선택 후 나머지 2장은 공개하지 않음.

## 3. 코드 변경안

현재 `index.html` 안의 모듈 기준.

### 3-0. 준비 (권장)
`index.html`은 3.9MB이고 대부분 base64 그림이다. 규칙 코드를 고칠 때 diff 검토가 어렵다.
- 그림 데이터(`src/content/art.mjs`)와 나머지 코드를 분리해 두고, 빌드 스크립트로 한 파일로 합치는 방식을 검토.
- 최소한 순수 규칙 모듈(`data.mjs`, `rules.mjs`, `game.mjs`)을 node에서 불러 테스트할 수 있는 스크립트(`tools/test-rules.mjs`)를 만든다.

### 3-1. 콘텐츠 `src/content/data.mjs`
| 대상 | 변경 |
|---|---|
| `balance` | 위 상수로 교체. `maxStars`, `maxElementStacks`, `elementBoostPercent`, `bodyElementPower`, `teamHp`, `maxTurns`, 더블/풀 보너스 삭제 |
| `scenarios` | 삭제 → `blinds` 테이블 (목표 점수, 몬스터 그림 ID, 보스 여부). 적 덱 삭제 |

| `combos` | 별 축 판정을 레벨 기준으로(페어/스트레이트/트리플), 보너스 수치 교체 |
| `compoundCombos` | 삭제 |

### 3-4. 렌더링 `src/rendering/compositor.mjs`
- 별 장식(배지·어깨·문장)을 별 개수 1/2/3 대신 **별 Lv 구간**으로: 예 Lv1+ 배지, Lv3+ 어깨, Lv5+ 문장.
- 속성 빛 효과(현재 2~3중첩)를 **속성 Lv 구간**으로.
- 조합 무기 레벨에 따라 무기 빛 강도 추가.
- 캐시 키에 레벨 구간 포함.

## 4. 필요한 리소스

### 새로 필요
| 리소스 | 수량 | 우선순위 | 비고 |
|---|---|---|---|
| 블라인드 몬스터 | 속성별 3 + 보스 1 = 4 | 높음 | 기존 스티커 화풍, 투명 배경. 없으면 속성 아이콘을 크게 띄워 임시 대체 |
| 보상 카드 뒷면 | 1 | 중간 | CSS로 임시 대체 가능 |
| 보상 등급 테두리 하/중/상 | 3 | 낮음 | CSS(색, 빛)로 충분 |
| 레벨 배지, 게이지 | - | - | CSS |

### 재사용
- 캐릭터 12종, 무기 3종, 조합 무기 9종, 속성 3종, 별, 별 등급 장식 4종, 배경.

### 더 이상 쓰지 않음
- 적 원정대 표시에 쓰던 화면 요소(그림은 캐릭터 그림을 공유하므로 삭제할 파일은 없음).

### 다음 단계에서 필요
- 효과음: 붙이기, 족보 성립, 배율 상승(음정 상승), 목표 돌파, 카드 뒤집기, 섞기, 등급 공개(상 전용), 실패, 클리어.
- 영어 문구.

## 5. 작업 순서

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 0 | 규칙 모듈 테스트 스크립트 + 그림 분리 | node에서 모듈 로드 |
| 1 | 콘텐츠 데이터 교체 | `validateContent` 통과 |
| 2 | 점수 계산 (족보, 상성, 조합 무기 9종) | 손으로 계산한 예제와 일치 |
| 3 | 게임 흐름 (블라인드, 턴, 판정, 보상 명령) | 명령만으로 런 한 판을 끝까지 진행 |
| 4 | 전투 화면 | 브라우저로 한 블라인드 진행 |
| 5 | 보상 야바위 화면 | 추적한 카드와 결과가 일치 |
| 6 | 렌더링 레벨 구간 | 레벨별 장식 확인 |
| 7 | 정보 창, 문구, 타이틀 | 화면 확인 |
| 8 | 수치 조정 | 직접 플레이 |

1~3단계는 화면 없이 테스트할 수 있다. 4단계부터 기존 화면이 깨지므로, 1~3단계를 한 번에 올리고 4~7단계를 이어서 올리는 두 묶음을 권장한다.

## 6. 구현 중 기본값으로 정할 것

설계에서 아직 열려 있는 항목. 아래 기본값으로 구현하고 플레이 후 바꾼다.
